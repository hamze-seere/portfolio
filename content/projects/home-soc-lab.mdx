## Overview

A small but realistic SOC environment running on my own hardware. Endpoints ship logs to a
Wazuh manager; I attack them from a separate VM and tune rules until the attacks are detected
with useful context and as few false positives as possible.

<Callout type="warning" title="Work in progress">

## Problem

Reading about detection engineering is not the same as doing it. I wanted hands-on practice with
the full loop a SOC analyst works in: **collect → detect → triage → tune**.

## My role

Everything: network design, VM provisioning, agent deployment, writing custom rules and decoders,
running attack simulations and documenting results.

## Tech stack

- **Wazuh** (manager, indexer, dashboard) on Ubuntu Server
- **Windows 10** endpoint with **Sysmon** (SwiftOnSecurity config as a baseline)
- **Ubuntu** endpoint with auditd
- **Kali Linux** as the attacker
- **Atomic Red Team** for repeatable, ATT&CK-mapped simulations
- Isolated **VirtualBox host-only network** — nothing in the lab can reach my home LAN

## Key features

- Centralised log collection from Windows (Sysmon, Security log) and Linux (auth, auditd)
- File integrity monitoring on sensitive paths
- Custom rules mapped to MITRE ATT&CK technique IDs
- A detection matrix tracking which simulations are detected, and how quickly

## Challenges & how I solved them

**Alert fatigue on day one.** Default rules fired hundreds of low-value alerts. I raised the
level on noisy rules and added context-specific exceptions rather than disabling them.

## Security considerations

- The lab network is host-only; the attacker VM cannot route to the internet or my LAN
- Malware samples (if any) are handled only inside snapshotted VMs
- Dashboard credentials are unique and not reused anywhere
